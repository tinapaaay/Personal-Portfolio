CSS Casebook.

Every bug has a story. A learning platform where you master CSS by investigating broken interfaces, testing a theory, and understanding exactly why the fix works.

01

The idea

Learn CSS the way you use it.

Real CSS work is mostly debugging: something looks wrong, and you have to find out why. CSS Casebook turns that into the lesson. Each case is a broken interface with a clear target, and you solve it by editing the CSS live.

A Field Guide sits alongside the cases with three lessons per chapter, short reviews, and progress summaries — no account needed.

02

What it does

Features

  • Live editing. Change the CSS and see the preview update instantly.
  • Original, current, and target. Compare where the case started, where it is now, and where it should end up.
  • Three-step hints. Hints get more specific only when you ask for them.
  • Clear feedback. Specific unresolved notes while you work, and a full resolution report when you solve it.
  • Saved progress. Drafts, hints, lessons, reviews, and completed cases are kept in the browser.
  • Built for every screen. Mobile workspace tabs with arrow-key navigation, reduced-motion support, and visible focus states.

03

How it works

Key decisions

Check the result, not the text

Fixes are validated against the rendered layout, so any correct CSS passes — not just one exact answer.

Sandboxed previews

Each case runs in an isolated iframe, so full multi-selector CSS works without breaking the Casebook's own interface.

One engine, 48 cases

A shared case engine handles the editor, preview, hints, checking, and reset. Case content lives in a separate data file.

Interactive labs

A Flexbox control room lets you change direction, wrapping, and alignment, and shows the generated CSS as you go.

Safe progress

Progress imports are validated before replacing anything, and a failed save restores the previous records.

No build step

Plain HTML, CSS, and JavaScript. Open the page and it runs — no installs, no bundler.

04

Quality

Checked at every size.

Browser regression tests cover all 48 starter and recommended solution pairs across the four main pages at five screen widths, plus dependency-free tests for saved progress. A manual smoke-test checklist is run before each release.

The neumorphic edition also fixed seven recommended solutions that the checker had been rejecting.
