Leemo Cocktails.

Drink well, live well. A landing page for a Santa Barbara cocktail bar where the scroll does the storytelling — from the opening pour to the last garnish.

Type
Landing page · motion design
Built with
HTML, CSS, JavaScript
Motion
GSAP, ScrollTrigger, Lenis
Links
Live ↗

A bar you can scroll through.

Most bar websites are a menu PDF and an address. I wanted Leemo to feel like walking in: a warm opening, the house rules, the drinks laid out one by one, and the ritual behind each glass.

The look stays simple — cream paper, deep blue type, and citrus artwork — so the motion can carry the mood.

Seven scenes

  • Opening. A counter runs from 000 to 100 while a lemon spins, then wipes away to reveal the hero.
  • Hero. "Drink well, live well" repeats around the cocktail photo; it pins while the lines drift apart.
  • Marquees. Two scrolling rows that speed up and skew with how fast you scroll.
  • Manifesto. The house rule lights up word by word as you read.
  • Menu. Scrolling down slides six drink cards sideways — each with ingredients, ABV, serving style, and price.
  • Ritual. Muddle, Squeeze, Shake, Garnish: four panels that stack, shrink, and dim as the next one arrives.
  • Visit. Hours, address, and a call-ahead note, closed by an animated wordmark.

Key decisions

Vertical scroll, sideways menu

ScrollTrigger pins the menu and maps scroll progress to the track's extra width, so it always ends exactly on the last card.

Measured, not guessed

That distance is recalculated after fonts load, after the page loads, and on resize, so the pin never cuts off a card.

Data-driven cards

The six drinks live in one array — name, image, color, ABV, style, price, and measures — and the cards are generated from it.

Smooth, velocity-aware scroll

Lenis smooths the scroll and reports its speed and direction, which drive the marquees and hide or show the header.

Touches for a mouse

Card tilt, hero parallax, a magnetic button, and a cursor that shows each drink's ABV — only on devices with a fine pointer.

One file, no build

Markup, styles, data, and motion live in a single index.html with six local images. Any static host can serve it.

Motion that knows when to stop.

If a visitor prefers reduced motion, there's no intro, no pinning, and no stacking — the menu becomes a normal horizontal scroll. If Lenis fails to load, GSAP still runs with native scrolling. Content is generated before any animation starts, so it's always there.

Next steps from my own notes: run the full manual test checklist across browsers, let keyboard users reach every off-screen card, add a pause control for the marquees, and optimize the images.
